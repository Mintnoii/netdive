# Proposal: 原文留存策略（上下文原文只在内存保留最近 N 次）

> 状态：**未排期特性（deferred）**，涉及隐私口径，需人类拍板后立项。

## 1. 痛点
NetDive 直接读本机会话 JSONL，因此抽屉里的「原文」可能把很久以前的提示词、密钥、业务文本原样展示并可一键复制。这是能力也是风险：
- 长期留存等于把历史 prompt 全量暴露在一个 Web 面板里；
- 面板关掉后这些文本仍留在磁盘（JSONL 本体），但我们没有明确策略说明谁在留、留多久。

## 2. 参考实现（已读源码）
`yetone/magpie`：
- 只在内存保留**最近 10 次请求**的原文，退出即清（`ctxtext.js` 的 `GONE.off` 文案明确写"只保留最近 {n} 次请求，仅在内存中"）；
- 提供脱敏（masking）开关：请求离开本机前把 secrets 换成占位符，回复再换回；
- 原文不可得时给出明确降级原因（`off` / `missing` / `cut` / `unread`），不伪造。

## 3. 设计要点（两档，需拍板）
- **A 档｜只读当前会话**：抽屉原文仅来自「当前激活会话的 JSONL」，切换会话即不可回看旧会话原文；UI 明示来源与范围。
- **B 档｜内存窗口**：额外限制只展示最近 N 次请求的原文（N 默认 10），更早条目显示 `原文未保留（超出内存窗口）`；不改磁盘、不删 JSONL。
- 共同要求：任何「拿不到原文」都必须给出明确原因，禁止静默空白。

## 4. 验收草案
- [ ] 超出范围的条目显示明确降级文案（含原因枚举），不显示空白也不伪造
- [ ] 策略开关的当前状态在 UI 可见
- [ ] 原文来源路径可见（会话 id + JSONL 文件名），便于用户自查

## 5. 依赖与风险
- 依赖：需先决定隐私口径（是否加脱敏）
- 风险：与「可回放原文」的可调试价值冲突，N 取值需实测调优
