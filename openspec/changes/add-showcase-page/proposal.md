# Proposal: 增设对外展示与简历演示独立页面 (/showcase)

## 背景与工程痛点
NetDive 当前定位为本地自主 Agent 的因果拓扑与人机门禁控制台，默认依赖本地伴生 Sidecar 服务 (`127.0.0.1:4560`)。
在用于个人简历项目展示、技术作品外发及面试投屏演示时，存在以下矛盾：
1. **外部访问强依赖本地服务**：外部访问者或面试官点开纯静态部署链接时，面对“服务未连接”的灰屏，无法快速感知系统核心价值；
2. **缺乏即时叙事动线**：真实 Agent 执行需要时间等待，缺乏一键预载的典型控制论灾难现场（死循环共振、超长 Prompt 膨胀微压缩对账、高危跨进程挂起）。

## 核心目标与技术选型
1. **路由与纯前端解耦**：
   - 增加 `/showcase` 路由（与 URL hash `#showcase` / Tab 同步支持），在无本地 4560 服务时 100% 独立稳定渲染；
   - 顶栏 Tab 增加 `showcase` 选项（执行控制台 / 压缩沙盒 / 场景演示）；
2. **4 大工业级控制论黄金演示场景**：
   - **场景 1：宏观回合编排与微观下钻**（双焦架构，按交互回合提纯 TurnNode，聚合意图与工具分布，支持一键下钻与全量 DAG 展开）；
   - **场景 2：死循环共振与自愈失败熔断**（Agent 连续命令报错 $\to$ 错误指纹识别 $\to$ L1 断言引擎触发 Gate 琥珀金挂起）；
   - **场景 3：长上下文精简与缓存保护**（Micro-Compactor 确定性骨架折叠，86.5k $\to$ 1.3k Token，WAL 存根无损还原与 Prompt Cache 90% 保真）；
   - **场景 4：高危人机缰绳与跨进程挂起**（高危命令触发 Promise.withResolvers 挂起抽屉，并支持模拟交互审批注入）；
3. **交互与时光机**：
   - 内置时光机播放控制器（播放/暂停/重置/Scrubber 全宽拖拽，移除无用死信息图例）；
   - 抽屉按需呈现：节点详情、微压缩透视板（带 1500 行日志 WAL 还原）、宏观回合瀑布图；
   - 100% 兼容 Vercel / Cloudflare Pages 纯静态托管，零服务器开销与秒开体验。
