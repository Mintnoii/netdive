# Proposal: 上下文卡片折叠记忆与折叠态堆叠细条

> 状态：**未排期特性（deferred）**。本档为立项占位与设计预研。

## 1. 痛点
上下文抽屉目前恒定占据视口底部 ~66vh。多数时候用户只想看「有没有超水位」这一眼信息，展开明细是低频动作；而每次打开都要占掉大半屏。

## 2. 参考实现（已读源码）
`yetone/magpie` `internal/gui/assets/context.js` 的 `ctxShut`：
- 卡片可折叠，折叠态仅保留头部：`标题 + tokens/window · 百分比 + 7 类 parts 堆叠细条 (.ctx-stack 6px)`；
- 折叠状态写 `localStorage['magpie.ctxShut']`，重开页面仍保持；
- 「因某个请求被点开而展开」时强制展开一次（`opts.open`），下一次绘制恢复用户选择。

## 3. 设计要点
- 抽屉新增折叠态：高度从 `min(66vh,640px)` 收缩到约 `h-9`，只留 一行摘要 + 堆叠细条 + 展开按钮；
- 折叠态同样持久化（`localStorage['netdive.ctxShut']`），与既有 `netdive.ctxLook` 分开存；
- 「点瓦片 / 点行打开浮层」时如果抽屉是折叠态，需先展开（否则找不到来源）；
- 堆叠细条与既有 7-part 配色字典复用同一份常量，避免两处颜色漂移。

## 4. 验收草案
- [ ] 折叠/展开切换不改变画布与播放控制位置（沿用现有零回流约束）
- [ ] 折叠状态刷新后保持；直接打开浮层时抽屉自动展开一次
- [ ] 堆叠细条宽度比例与 7 个 part 的 tokens 占比一致（容差 <1%）

## 5. 依赖与风险
- 依赖：暂无，改动集中在一个组件
- 风险：与「恒定高度」既有断言冲突，需要新增「折叠态高度 = X」契约测试
