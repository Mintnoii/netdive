# Proposal: React Flow 画布排版、视口跟焦与折叠交互全面治理

## 1. 痛点背景与动机 (Problem Statement)
在 NetDive 接入真实 Pi / Claude 会话 JSONL 流水后，长链 ReAct 轨迹（数十到上百步）在 React Flow 画布展示中暴露出多项严重的交互与排版缺陷：
1. **初始加载与切页白屏（视口漂移）**：节点坐标按全量一次性线性递增累加（`x = i * 280`）。分页切片（如 51-100 步）后，渲染节点的 x 坐标在 14,000px 之外，而 React Flow 视口停留在原点，导致画布大面积空白，必须手动点击 `Fit View` 才能找回节点；
2. **空间利用率极低（单一水平一字长蛇阵）**：所有节点自左向右一条直线排开，垂直高度大面积闲置，高宽比极度畸形；
3. **时间轴拖动视口跑飞**：滑动底部时间轴 Scrubber 时，视口中心未与活动节点建立锚定绑定，节点像走马灯一样飞出视口；
4. **同构折叠（Folding）状态响应失效**：`App.tsx` 中切换 `isFoldingEnabled` 仅变更了单个布尔状态，未重新基于原始事件派生聚合图，导致界面毫无变化；且缺乏对展开后总节点数激增与视口保护的考虑；
5. **节点 Hover 上下文弹窗干扰与性能损耗**：节点卡片上残留复杂的 hover tooltip 定时器与弹窗逻辑，遮挡操作且引发不必要的重排。

## 2. 核心架构设计与解决方案 (Design & Principles)
1. **多行蛇形/分行紧凑布局 (Snake / Row-Wrapped Grid Layout)**：
   - 告别一维一字长蛇排布，引入智能分行布局（例如每行 6~8 个节点，保持水平主流向 + 垂直折行导向），充分利用现代化 16:9 宽屏画布的纵向空间；
   - 保持自愈分叉与纠偏分支的纵向偏移（Lane Branching），视觉层次分明；
2. **视口自动跟焦与切片相对归一化 (Viewport Auto-Tracking & Normalization)**：
   - 在 ReactFlow 内部通过 `useReactFlow()` 或挂载 `CanvasViewportController`，在会话切换、翻页（上/下 50 步）、折叠切换以及首屏加载完成时，平滑调用 `fitView({ padding: 0.2, duration: 300 })`；
   - 当用户在时间轴拖动时，提供视口相机跟随当前 Step 对应节点位置的机制；
3. **同构折叠真实响应与状态统一收敛**：
   - 在 `App.tsx`（及 Replay 页面）中，将原始会话事件 `rawEvents` 作为状态基准，由 `useMemo` 根据 `isFoldingEnabled` 动态派生 `displayEvents`，进而派生 `nodes` 与 `edges`；
   - 确保点击“折叠同构 / 展开同构”能即时重建 DAG 拓扑并自适应重算布局；
4. **移除节点 Hover 上下文弹窗**：
   - 彻底清理 `AgentNode.tsx` 内的 hover timer、悬浮上下文 tooltip 和多余 DOM 结构，轻装上阵。

## 3. 验收标准 (Acceptance Criteria)
- [ ] 页面初次加载任意真实会话，节点 100% 自动在视口内居中适配（无需手动点 Fit View）；
- [ ] 画布节点呈现合理的多行/网格紧凑排版，垂直与水平空间利用率均衡；
- [ ] 点击“上 50 步 / 下 50 步”或拖动底部时间轴，视口平滑聚焦到当前批次节点，绝无白屏或节点飞出视口现象；
- [ ] 点击底部“折叠同构 / 展开同构”按钮，画布节点能够即时展开/聚合，且连线和节点位置自适应更新；
- [ ] 节点不再触发悬浮上下文弹窗，hover 时仅保留素雅的边框微高亮；
- [ ] 现有测试（包含 transcriptParser、microCompactor 等单测）全部通过，无构建与 Lint 错误。
