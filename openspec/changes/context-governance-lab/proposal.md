## 1. 业务背景与问题痛点

长程 Agent（Coding Agent / 数据流水线）在多轮 ReAct 执行中，上下文会持续膨胀并引发三类问题：
1. **指令遗忘**：会话变长后，最初的目标与硬约束被稀释，模型开始偏离原始要求；
2. **长载荷挤爆窗口**：单测、构建、全库向量比对动辄上千行输出，全量塞进上下文造成严重 Token 浪费；
3. **压缩时机不当**：按固定轮数机械压缩会切断正在进行的推理链，必须在子任务闭环的安全点才触发。

本项目在 NetDive 中新增一个**交互式上下文工程演练画布**，基于真实历史会话（Ghost 知识库炼化流水线），逐步演示并让用户亲手操作各类上下文治理手段。

## 3. 核心架构决策收口

### 3.1 ContextState 统一装配对象（单一真源）
`contextGovernanceEngine.ts` 定义 `ContextState`，四层结构：
- `budget`：Token 上限、原始累积、优化后占用、剩余空间、节省比例；
- `staticPrefix`：系统提示词 + 目标 + 工具 + 约束，配 SHA-256 前缀哈希与 `isCacheStable`；
- `workingSet`：当前活跃步骤；
- `offloadedLedger`：清理记录 + `backupStore`（索引 ID → 完整原文），支撑取回与回滚。

### 3.2 场景数据（真实业务，9 步）
Ghost 知识库真实炼化流水线：素材解析 → 查重 → 概念预热 → 并发抽取三卡 → 去AI痕定稿 → 全库向量对撞 → 卡片落盘 → MOC 反链 → wiki:lint 终检。前半程积累的冗余草稿，正是"打包精简"与"折叠聚合"的演示载体。

### 3.3 画布交互规范
- React Flow 主干拓扑 + 自动平滑追焦（无 fitView 冲突）；
- 同构调用默认展开为 3 个子节点（间距 150px，青色虚线串联），可折叠为 `x3` 聚合节点；
- 连线出口动态计算：上一步展开时用最后一个子节点作 source，保证链路贯通；
- 节点可拖动，位置用覆盖表记忆，重置时清空。

### 3.4 底部常驻面板规范
- 顶栏放步进控制（上一步/下一步/重置）+ 核心 Token 指标 + 展开收起；
- 展开后双层：上层左右为"Token 剩余容量 / 历史清理流水账"，下层全宽为"固定前置上下文"；
- 固定前置上下文用 12 栏不等分（4 块内容），整块固定高度，里程碑横向滚动不撑高。
