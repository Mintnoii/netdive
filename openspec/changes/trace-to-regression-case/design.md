# Design: trace-to-regression-case (失败会话用例提纯与回归评测工作台)

## Context

原「测试对比」模块由于名称和定位偏向末端比对，引发了认知割裂。本设计将核心工程定位重塑为「从失败会话中提纯回归测试用例」，并将原本黑盒的抽取逻辑白盒化拆解为 4 步可视化流水线，同时引入内置全特性演示数据与一键模拟重跑机制。

## Goals / Non-Goals

- Goals
  - 核心心智明确：主入口为「失败用例提纯」，对账对比归位为该用例底部的「验收对账」环节。
  - 白盒化呈现：在页面中可视化展示 4 步抽取流水线（故障分级 ➔ 签名降噪 ➔ WAL 载荷剥离 ➔ 三维断言合成）。
  - 内置经典交互式演示用例：完整承载 5 大技术点（L1/L2共振、WAL指针、三维断言、Tracing Tag），并提供一键模拟重跑对账交互。
  - 与上下文演练的底层同构：明确「冷热分层与指针引用」在上下文压缩与用例轻量化中的通用性。
- Non-Goals
  - 不在前端构建庞大的虚拟机或模拟终端真实执行 bash 命令。
  - 不做侵入式远程上报，100% 保持 Local-First 纯本地架构。

## Decisions

### D1 Tab 命名收敛为「用例提纯」
- 方案：顶栏与页面主标题统一为「用例提纯」，副标题明确为*“失败会话特征捕获 ➔ 提取测试用例与断言基线 ➔ 终端重跑自动对账”*。
- 理由：一针见血指明当前页面的输入（失败现场）与产出（测试用例），消除“刚进来跟谁对比”的心智割裂。

### D2 提纯流水线动态靶向治理 (Targeted Case Distillation)
- 方案：彻底废除千篇一律的固定 4 步八股文，**根据第一幕检出的事故病灶动态生成对症治理步骤**：
  1. 识别到 `L2 循环共振死锁` ➔ 动态生成「因果 DAG 倒查切片与震荡识别」步骤；
  2. 识别到 `上下文严重膨胀` ➔ 动态生成「证据载荷冷热分层与 WAL 指针化」步骤；
  3. 识别到 `动态环境噪声污染` ➔ 动态生成「环境无关正则模板化与指纹去噪」步骤；
  4. 识别到 `L3 安全门禁熔断` ➔ 动态生成「破坏性指令模式提取与拦截断言」步骤；
  5. 末尾统一追加「三维防退化断言契约合成」汇聚步骤。
- 理由：步骤卡片明确打上 `🎯 靶向治理 · 病灶 0X` 标签，每一个步骤都与上方检出的病灶 1 对 1 靶向对齐，体感真实有力，杜绝“只要是会话就走固定四步”的死板感。

### D3 全特性内置演示场景库与模拟对账
- 方案：
  - 在 `regressionDemoScenarios.ts` 中内置 3 大典型业务场景（Ghost 炼化死锁、伴生服务崩溃与路径噪声、GitHub 门禁熔断）；
  - 演示库默认全员待提炼 (Inbox)，让用户亲手点击体验从事故到用例的动态演练；
  - 在前端提供「⚡ 一键模拟优化重跑」按钮，调用纯函数 `createDemoChallengerReport()` 注入修复后的会话指标，瞬间渲染全绿对账面板。
- 理由：消灭因本地真实会话特性残缺导致演示/面试断层的痛点。

### D4 架构同构：冷热分层与 WAL 指针
- 方案：回归用例不存巨型 stdout，只存 `pointerId`，与上下文工程中的 `Micro-Compactor` 共享 WAL 离线引用机制。
- 理由：用例单文件保持在 5KB 内，毫秒级快速加载与持久化。

### D6 单卡片分区布局（最终布局）
- 方案：右侧详情区收敛为**一个卡片**，内部三段：
  1. **顶部**：会话标题、来源、状态徽标（翻车现场 / 已治愈 / 已治理 N 个病灶）；
  2. **上半区**（左右两栏）：左＝原始任务目标 + 放大的三体征卡片（峰值 / 前缀 / 输出体积）；右＝带追踪标签的重跑指令（初始即含占位文案，治理病灶后自动填入对应指纹与准则）+ 一排精简的同等大小按钮（导出 / 移出 / 复制指令 / 重置会话 / 模拟重跑）；
  3. **下半区**：检出病灶固定高度容器，内部滚动，逐行三栏（病灶描述 / 原始数据 / 提纯产物），支持逐病灶治理与撤销。
- 理由：单一卡片让整页信息一屏可达；上半区把「任务目标 ↔ 重跑指令」并置，下半区固定高度内部滚动，彻底解决多病灶时展开产物把指令顶出视口的问题；按钮统一精简为小尺寸，减少视觉噪音。
- 方案：
  - 摒弃常驻的「四步流水线板块」。页面默认只有顶部的「现场档案」：原始任务目标 + 检出的病灶清单（每个病灶旁附一条小巧的「建议处理手段」提示）+ 醒目体征画像（峰值 Tokens / 前缀缓存 / 工具输出体积）；
  - 检出病灶区改为**单列行式**：一行一个病灶，左侧是病灶描述、右侧是该会话的**真实原始数据 / 事件流**（提纯过程里左侧的那些真实数据）；每个病灶自带「治理 / 撤销治理」按钮，支持**逐病灶独立治理与撤销**，另设「一键治理全部 / 撤销全部」批量按钮（批量即原来的提纯过程）；
  - 治理某个病灶后：左侧描述原地翻牌为治愈结果，右侧**保留原始数据的同时追加一块「提纯产物」**（前后对比同屏可见）；
  - **只要有任意一个病灶被治理**，下方即显现「测试用例规格与重跑指令」：左侧验收准则、右侧重跑指令都**只包含已治理病灶**且一一对应（治理 1 个就 1 条、治理 2 个就 2 条），末尾附一条全局防退化准则；
  - 点击「模拟重跑」**不向下冒出新大屏**，而是让顶部会话**原地治愈翻牌**。
  - 治愈态提供「重置会话」按钮，一键把会话还原回故障前样子。
- 理由：提纯过程展示的必须是**数据本身被处理成什么样**，而非技术点定义的文字复述；内嵌区块比弹窗更自然、不打断页面叙事；把整个闭环收敛到同一视觉区域，用户直接看到「同一个坏会话被提纯、再被治愈成好会话」的前后对比。

## 数据流与状态流转

```text
[失败事故现场 (检出病灶清单)]
        ↓ 
[动态靶向提纯流水线]
  ├── 🎯 靶向治理 · 病灶 01 (如 DAG 剪枝 / 退出码锚定)
  ├── 🎯 靶向治理 · 病灶 02 (如 WAL 冷热解耦 / 路径去噪)
  └── 📦 全案汇聚 · 考卷合成 (功能 + 资源防退化 + 流程治理)
        ↓
[RegressionCase 固化入库 (localStorage)]
        ↓
[重跑阶段：复制 Repro Prompt (含唯一追踪标签)]
        ↓ (真实终端执行 OR ⚡ 一键模拟重跑)
[治愈对账大屏]
  ├── 【核心首位】原始事故病灶 ➔ 治愈对账清单 (逐项对账实况)
  └── 三维量化检查面板 (指纹清零 + Token 降 63% + 门禁 0 违规)
```
